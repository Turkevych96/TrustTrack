# AGENT.md

## Проект
TrustTrack - небольшое локальное Django-приложение для учета семейных долгов между доверенными пользователями.

Цель проекта - не банковская система промышленного уровня. Цель - хранить понятную историю: кто у кого занял деньги, когда, под какой годовой процент, какие возвраты были сделаны и как начислялись проценты со временем.

## Стек
- Python >= 3.14
- Django 6
- Django Legacy: классические Django views, forms, templates и Django admin там, где это удобно
- SQLite database через `db.sqlite3`
- Управление зависимостями через `uv`

Не добавлять тяжелые frontend-фреймворки, REST API, фоновые воркеры или внешние сервисы, если пользователь явно этого не попросил.

## Границы продукта
Проект предназначен для малого приватного круга людей, например одной семьи.

Приложение может хранить:
- локальные данные Django-аутентификации;
- записи о членах семьи/пользователях;
- записи о долгах;
- записи о возвратах;
- записи о начислении процентов;
- журнал транзакций и аудита.

Приложение не должно хранить:
- данные банковских карт;
- учетные данные банковских аккаунтов;
- внешние платежные секреты;
- лишние персональные чувствительные данные.

## Основная доменная логика
Долг создается, когда один пользователь занимает деньги у другого пользователя.

Пример: пользователь A берет деньги в долг у пользователя B в конкретную дату под годовую ставку, например 3.5%.

Система должна поддерживать:
- кредитора и заемщика;
- сумму основного долга;
- годовую процентную ставку;
- дату начала долга;
- частичные и полные возвраты;
- ежемесячное начисление процентов;
- журнал транзакций/историю изменений;
- текущий остаток долга.

## Правила расчета процентов
Использовать простые ежедневные проценты.

Ежедневный процент рассчитывается от текущего остатка основного долга за каждый день.

Если заемщик возвращает часть долга в течение месяца, база для начисления процентов меняется с даты возврата.

Накопленные ежедневные проценты проводятся/начисляются в начале следующего месяца.

Для всех денежных сумм и процентных расчетов использовать `Decimal`. Не использовать `float` для финансовой математики.

## Принципы разработки
Держать проект простым и легким для локального запуска.

Предпочитать читаемый Django-код сложным абстракциям.

Для финансовой логики предпочитать явные модели и сервисы. Расчет процентов должен быть изолирован и покрыт тестами.

Не коммитить локальные артефакты: `.venv/`, `db.sqlite3`, кэши, логи и IDE-файлы.

Перед изменением поведения финансовых расчетов добавлять или обновлять тесты, которые показывают ожидаемый результат.
